# OctoAcme Project Management Docs

This directory contains OctoAcme's project management processes and working agreements. Use these documents as a shared reference for planning and delivering cross-functional projects.

## Project management overview

OctoAcme manages projects through a customer-focused, iterative lifecycle: initiate work around a clear problem and measurable outcomes, plan scope and milestones, execute in small increments, release with verification, and capture lessons in retrospectives. Initiation aligns stakeholders on goals, success measures, resources, and initial risks; planning turns approved work into a prioritized backlog with acceptance criteria, estimates, dependencies, and a Definition of Done.

Project Managers coordinate schedules, delivery, risks, and communication; Product Managers set direction, prioritize work, and measure outcomes; developers build and test; and QA validates acceptance criteria. Stakeholders provide input and approvals. Teams track work on a project board, use regular standups and delivery reviews to surface progress and blockers, and share weekly or milestone-based stakeholder updates. Risks are recorded, monitored, and escalated through the PM and Product Lead to the sponsor when needed.

Quality is built into delivery through clear acceptance criteria, code review, automated tests and CI checks, security scanning, and appropriate manual QA. Releases require acceptance criteria to be met, passing checks, release notes, smoke tests, and a rollback plan, followed by deployment verification and stakeholder communication. Retrospectives after sprints, releases, milestones, or incidents turn feedback into a small set of owned, trackable improvements.
